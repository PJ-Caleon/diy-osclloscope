## Learn (about 30 minutes)

**What happens at power-on.** The CPU reads two words from the start of flash. Word 0 becomes the stack pointer. Word 1 is the address of the first function to run: `Reset_Handler`. That list of addresses is the **vector table**.

**Why Reset_Handler exists.** C expects two things before `main`: variables with start values (like `int x = 42;`) already in RAM, and zeroed variables set to 0. RAM is empty at power-on. So `Reset_Handler` is the moving crew: it copies the start values from flash into RAM (`.data`), zeroes the rest (`.bss`), then calls `main`.

**The linker script is a floor plan.** It says which room (FLASH or RAM) each piece lives in. `.data` is special: it lives in RAM while the program runs, but its start values are STORED in flash. Two addresses: where it runs (VMA, in RAM) and where it is stored (LMA, in flash). `> RAM AT> FLASH` says exactly that.

**Linker symbols are addresses, not variables.** `_sdata` marks a place. In C you write `&_sdata` to get that place. This is your `&` practice again.

**No libc.** You build with `-nostdlib`, so there is no `memcpy`. You write your own word copy and zero loops. `-lgcc` at the end of the link line provides helper code such as 64-bit divide. `-fno-tree-loop-distribute-patterns` stops GCC turning your loops back into `memcpy` calls.

**Thumb bit.** Cortex-M runs Thumb code only. Function addresses in the vector table must have bit 0 set. The compiler and linker do this for you, so word 1 looks odd (like ...45).

## Worked example: walking pointers and a custom section

```c
/* WORKED EXAMPLE (M1-02): walking pointers + a custom linker section. */
#include <stdint.h>

/* Add up every word from p up to (not including) end. */
uint32_t sum_words(const uint32_t *p, const uint32_t *end)
{
    uint32_t s = 0;
    while (p < end) {
        s += *p;        /* read the word p points at */
        p++;            /* move to the next word     */
    }
    return s;
}

/* A table the linker puts in its own section called .cfg (in Flash). */
__attribute__((section(".cfg"), used))
const uint32_t cfg_words[3] = { 10, 20, 30 };

extern const uint32_t _scfg, _ecfg;      /* symbols the linker script creates */

uint32_t cfg_total(void)
{
    return sum_words(&_scfg, &_ecfg);    /* & turns a symbol into its address */
}
```

The linker fragment that creates `_scfg` and `_ecfg` (a section called `.cfg`):

```
  .cfg :
  {
    . = ALIGN(4);
    _scfg = .;            /* start of the section */
    KEEP(*(.cfg))
    _ecfg = .;            /* end of the section   */
  } > FLASH
```

`sum_words` is the shape of both `copy_words` and `zero_words`: `while (p < end) { ... p++; }`.

## Cheat sheet

| Item | Value |
|---|---|
| FLASH | `FLASH (rx) : ORIGIN = 0x08000000, LENGTH = 32K` |
| RAM | `RAM (rwx) : ORIGIN = 0x20000000, LENGTH = 10K` |
| `_estack` | `ORIGIN(RAM) + LENGTH(RAM)` = 0x20002800 |
| Symbols the startup code needs | `_sidata` (where .data is stored in flash), `_sdata`, `_edata` (where it runs in RAM), `_sbss`, `_ebss` |
| `_sidata` | `LOADADDR(.data)` |
| .text goes | `> FLASH`; contains `*(.text*)` and `*(.rodata*)` |
| .data goes | `> RAM AT> FLASH` |
| .bss goes | `> RAM`; contains `*(.bss*)` and `*(COMMON)` |
| `.isr_vector` | first in FLASH, `KEEP(*(.isr_vector))` (given) |
| Vector table (16 slots) | 0 stack pointer, 1 Reset, 2 NMI, 3 HardFault, 4 MemManage, 5 BusFault, 6 UsageFault, 7-10 reserved, 11 SVCall, 12 DebugMon, 13 reserved, 14 PendSV, 15 SysTick |
| Reset order | copy .data, zero .bss, call main |
| Compiler flags | `-mcpu=cortex-m3 -mthumb -Os -g -std=gnu11 -Wall -Wextra -ffreestanding -fno-tree-loop-distribute-patterns -ffunction-sections -fdata-sections -Iinclude` |
| Linker flags | `-mcpu=cortex-m3 -mthumb -nostdlib -T ld/stm32f103c6.ld -Wl,-Map=build/firmware.map -Wl,--gc-sections` |
| `objcopy` | `arm-none-eabi-objcopy -O binary in.elf out.bin` |
