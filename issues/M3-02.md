## Learn (about 30 minutes)

**A framebuffer is a picture in RAM.** You draw into it with ordinary C. Then you send it to the screen in one go (the flush). 128 x 64 pixels, 1 bit each = 8192 bits = 1024 bytes.

**The SSD1306 memory layout is in pages.** The screen is 8 pages (horizontal strips) of 8 pixel rows. Each page has 128 columns. One byte = one column of one page: bit 0 is the TOP pixel of that strip, bit 7 the bottom. So pixel (x, y) lives in byte `(y / 8) * 128 + x`, bit `y % 8`.

**Setting and clearing a bit.** `byte |= mask` sets, `byte &= ~mask` clears, where `mask = 1 << bit`.

**Commands and data.** Every I2C write to the OLED starts with a control byte. `0x00` means "the bytes after me are commands". `0x40` means "the bytes after me are pixel data".

**Fake bus.** `ssd1306_init(bus)` takes a function pointer. On the board you pass `i2c_write`. In the tests you pass `fake_i2c_write`, which only records what you send. So you can prove the exact bytes without an OLED.

**Flush.** Send one command write to set the window (columns 0 to 127, pages 0 to 7), then send the 8 pages as 8 data writes of `0x40` plus 128 bytes.

## Worked example: an 8x8 LED-matrix framebuffer

```c
/* WORKED EXAMPLE (M3-02): an 8x8 LED-matrix framebuffer. One byte per row, bit x = column x. */
#include <stdint.h>
uint8_t m[8];

unsigned m_index(unsigned x, unsigned y) { (void)x; return y; }      /* which byte?  */
unsigned m_bit(unsigned x)               { return x; }               /* which bit?   */

void m_clear(void) { for (unsigned i = 0; i < 8; i++) m[i] = 0; }

void m_pixel(unsigned x, unsigned y, int on)
{
    if (x >= 8 || y >= 8) return;                        /* ignore off-screen pixels */
    uint8_t mask = (uint8_t)(1u << m_bit(x));
    if (on) m[m_index(x, y)] |= mask;                    /* set the bit              */
    else    m[m_index(x, y)] &= (uint8_t)~mask;          /* clear the bit            */
}
```

Same idea with a smaller screen: one byte per row, bit x = column x. Yours uses `fb_index` and `fb_bit` instead of `m_index` and `m_bit`.

## Cheat sheet

| Item | Value |
|---|---|
| Screen | 128 x 64, 8 pages x 128 columns, 1024 bytes in `g_fb` |
| Pixel (x, y) | byte `(y / 8) * 128 + x`, bit `y % 8` (bit 0 = top row of the page) |
| Examples | (0,0) byte 0 bit 0; (5,9) byte 133 bit 1; (127,63) byte 1023 bit 7 |
| Ignore | x >= 128 or y >= 64 |
| OLED address | `SSD1306_ADDR` = 0x3C |
| Init bytes (25, in order) | `AE D5 80 A8 3F D3 00 40 8D 14 20 00 A1 C8 DA 12 81 CF D9 F1 DB 40 A4 A6 AF` |
| Init transaction | ONE write of 26 bytes: `00` then the 25 bytes |
| Flush, part 1 | one write of 7 bytes: `00 21 00 7F 22 00 07` |
| Flush, part 2 | 8 writes of 129 bytes: `40` then 128 bytes of `g_fb` starting at `page * 128`, for page 0 to 7 |
| Bus function type | `int (*bus_write_fn)(uint8_t addr, const uint8_t *buf, uint16_t len)` returns 0 for OK |
| Use of errors | return the first non-zero result and stop |
| Test bus | `fake_i2c_write` (records each transaction) |
| Real bus | `i2c_write` |
| No libc | write copy loops yourself (`for`), no `memcpy` |

Card C1 in disguise: set or clear one bit in a byte: `b |= m` / `b &= ~m`.

| If it fails, look here | Likely cause |
|---|---|
| blank screen | `ssd1306_init` bytes wrong (count 25), or the init write NACKed: print its return value |
| screen full of noise | the init was never sent; or flush sends 128 bytes instead of 129 (control byte missing) |
| picture upside down or mirrored | bytes `A1` and `C8` in `init_seq` wrong |
| lines have gaps of 8 rows | `fb_bit` uses `y / 8` instead of `y % 8` |
| `test_flush` fails at length | each page write is 1 + 128 = 129 bytes |
| screen shifted by 2 columns | some modules use the SH1106 chip instead: not covered by this kit |
