## Learn (about 30 minutes)

**The super loop.** There is no operating system. `main` ends in `for (;;)`. Inside, every pass checks "is there something to do?" and does it quickly. Slow waiting is forbidden. Interrupts only set flags (like SysTick advancing `millis`); the loop reads them.

**Your loop is built from pieces you own.**

1. Buttons: for each of the three buttons, `debounce_update` on the raw bit; a press returns 1: call `ui_handle(&ui, event)`. A change in settings means the old capture is stale: restart it with the new rate.
2. Capture: `sampler_wait(1)` asks "done yet?" with one try, so the loop never sits waiting. If done: `sampler_stop`, `scope_process`, `scope_draw`, `ssd1306_flush`, `sampler_start`.
3. LED heartbeat: toggle every 500 ms with `reached` (card C6). It tells you the loop is alive.

**Event numbers.** Button 0 = MODE = `EV_MODE` (1), button 1 = UP = `EV_UP` (2), button 2 = DOWN = `EV_DOWN` (3). So event = button index + 1.

**Three small functions, one big job.** `scope_process` finds numbers. `scope_header` makes the text. `scope_draw` paints the frame. `main` glues them. Keep each short.

**Honest limits.** At 8 kHz and slower (2 ms/div and up) the 1 kHz test signal is sampled fewer than 10 times per period. At 1.6 kHz and 800 Hz it is below the sampling limit: the picture and the frequency are wrong (aliasing). The scope is not broken: the signal is faster than the rate.

## Worked example: a flag-driven super loop

```c
/* WORKED EXAMPLE (M6-01): a flag-driven super loop. The interrupt only sets a flag; the loop does the work. */
#include <stdint.h>

static volatile uint8_t tick_flag;            /* volatile: an interrupt changes it behind the loop's back */
void SysTick_Handler(void) { tick_flag = 1; } /* ISR: set the flag and leave. Nothing else.               */

extern void read_sensor(void);
extern void update_screen(void);

int main(void)
{
    unsigned ticks = 0;
    for (;;) {                                /* the super loop never ends */
        if (tick_flag) {
            tick_flag = 0;                    /* clear first, then work    */
            ticks++;
            read_sensor();
            if (ticks % 100u == 0u) update_screen();
        }
    }
}
```

Your `main` has the same shape: the loop checks conditions, does bounded work, never blocks.

## Cheat sheet

| Item | Value |
|---|---|
| `scope_t` | `{ ui_t ui; uint16_t *cap; int trig; unsigned start; stats_t st; uint32_t freq_hz; }` |
| `scope_init` | given |
| Window | 128 samples from `cap + start`; `start` is at most 127, so it always fits in 256 |
| Trigger scan | the first 128 samples (`128u`), using `sc->ui.rising` |
| Level | `mv_to_counts` of `sc->ui.level_mv` |
| Frequency level | (min + max) / 2 |
| Minimum swing for a frequency | `max - min >= 100` counts |
| Sample rate | `tdiv_to_fs(sc->ui.tdiv_idx)` |
| Labels | `tdiv_label[idx]`, `vdiv_label[idx]` (strings); mode letter `"TVLE"[sc->ui.mode]` |
| Text helpers | `fmt_hz(out, hz)`, `fmt_mv(out, mv)` return the length; `line1[n++] = ' ';` adds one character |
| Expected text (default UI, 1 kHz 25 % PWM at 1 ms/div) | line 1 `1ms 1V 1.00kHz R`; line 2 `T p3.29V a0.83V` (the real signal swings 3 to about 4090 counts) |
| Draw | clear, two text lines, grid, plot (see STEP 3) |
| Event from button i | button index + 1, cast to `ui_event_t` |
| `main` order of init | `clock_init`, `led_init`, `uart_init` (+ banner), `adc_init`, `sampler_init`, `pwm_init` + `pwm_set_duty(25u)`, `i2c_init`, `ssd1306_init(i2c_write)`, `buttons_init`, `scope_init(&g_scope)` |
| Capture start | `sampler_start` with `tdiv_to_fs(ui.tdiv_idx)` |
| Done check | `sampler_wait(1u)` returns 0 |
| Globals in `main.c` | `static scope_t g_scope; static debounce_t g_deb[3];` (and a `start_capture` helper) |

|---|---|---|
| 0 | PB12 | `EV_MODE` |
| 1 | PB13 | `EV_UP` |
| 2 | PB14 | `EV_DOWN` |
