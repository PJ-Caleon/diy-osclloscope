**Card C1  Change a field (clear with a mask, then set)**

```
REG &= ~(MASK << SHIFT);     /* 1. clear the field  */
REG |=  (VALUE << SHIFT);    /* 2. write the value  */
MASK = (1 << WIDTH) - 1      /* width 1 -> 0x1, 2 -> 0x3, 3 -> 0x7, 4 -> 0xF */
In code:  reg = field_set(reg, SHIFT, WIDTH, VALUE);
```

Erase one box on a paper form, then write in the box. If you skip the erase, old ink and new ink mix.

```
field_set(0x44444444, 20, 4, 2)
  clear bits 23..20 -> 0x44044444
  set 2 in them     -> 0x44244444
```

| register value | shift | width | value | result |
|---|---|---|---|---|
| 0x44444444 | 20 | 4 | 2 | 0x44244444 |
| 0xFFFFFFFF | 4 | 4 | 0 | 0xFFFFFF0F |
| 0x00000000 | 8 | 3 | 5 | 0x00000500 |

**Card C2  GPIO pin nibble (CRL or CRH)**

```
shift = (pin % 8) * 4          /* each pin owns 4 bits */
register = (pin < 8) ? CRL : CRH
gpio_cfg(GPIOx, pin, NIBBLE);   /* = C1 with width 4 */
```

A hotel corridor: 8 rooms per floor, 4 bits per room. Pins 0-7 are on floor CRL, pins 8-15 on floor CRH.

```
PC13: 13 % 8 = 5, shift = 5 * 4 = 20, register CRH.
PA2 : shift = 2 * 4 = 8,  register CRL.
```

| nibble | meaning |
|---|---|
| 0x0 | analog input |
| 0x4 | floating input |
| 0x8 | input with pull-up or pull-down (ODR bit picks which: 1 = pull-up) |
| 0x2 | output, push-pull, 2 MHz |
| 0x3 | output, push-pull, 50 MHz |
| 0xA | alternate function, push-pull, 2 MHz |
| 0xB | alternate function, push-pull, 50 MHz |
| 0xF | alternate function, open-drain, 50 MHz |



## Learn (about 30 minutes)

**The ST-Link is your key to the chip.** It talks SWD (two wires, SWDIO and SWCLK) to the debug port inside the Cortex-M3. **OpenOCD** is the program on your PC that drives the ST-Link. Its command `program file.elf verify reset exit` writes flash, reads it back to compare, resets the chip, and quits.

**Why `verify`?** It reads the flash back and compares it. If a byte differs you hear about it.

**Crude delay.** Right now the chip runs on its internal 8 MHz oscillator. A loop that counts to a big number with a `volatile` counter wastes time. `volatile` stops the compiler deleting the empty loop. It is crude and temporary: in M1-04 you replace it with a real clock.

**Two CI jobs.** CI runs on GitHub every time you push. The `host-tests` job (given) runs your unit tests. You add a `firmware` job that installs the ARM compiler and runs `make firmware`. If either job turns red you know which half broke.

**Power rule.** The board gets power from the ST-Link 3.3 V pin. Never also plug USB.

## Worked example: a small cross Makefile with a flash recipe

```
# A small cross Makefile for a program called "demo". Recipe lines start with a TAB.
CROSS  = arm-none-eabi-
CFLAGS = -mcpu=cortex-m3 -mthumb -Os -g -ffreestanding -Iinclude
LDFLAGS = -nostdlib -T link.ld

build/demo.elf: demo.c start.c link.ld
	@mkdir -p build
	$(CROSS)gcc $(CFLAGS) demo.c start.c $(LDFLAGS) -lgcc -o $@

size: build/demo.elf
	$(CROSS)size $<

flash: build/demo.elf
	openocd -f interface/stlink.cfg -f target/stm32f1x.cfg -c "program build/demo.elf verify reset exit"
```

Read it: one rule builds the ELF; `size` prints sizes; `flash` depends on the ELF and runs OpenOCD with the `program ... verify reset exit` command.

## Cheat sheet

| Item | Value |
|---|---|
| ST-Link wires | SWDIO, SWCLK, GND, 3V3 to the 4-pin header on the board |
| BOOT jumpers | both at 0 |
| Probe the chip | `st-info --probe` |
| Flash command | `openocd -f interface/stlink.cfg -f target/stm32f1x.cfg -c "program build/firmware.elf verify reset exit"` |
| OpenOCD messages when all is well | `** Programming Finished **`, `** Verified OK **`, `** Resetting Target **` |
| Clone chips: unexpected id error | put `-c "set CPUTAPID 0x2ba01477"` FIRST on the command line |
| Blink loop shape | `for (;;) { led_toggle(); for (volatile uint32_t i = 0; i < N; i++) { } }` |
| Starting N | 500000 (tune until about one toggle per second; not measured) |
| CI file: indent | job names sit 2 spaces in; `runs-on` 4; list items `- ` 6 |
| CI job shape | `name: runs-on: steps: - uses: actions/checkout@v4 - name: ... run: ...` |
| Install ARM compiler on the CI machine | `sudo apt-get update && sudo apt-get install -y gcc-arm-none-eabi` |

## Cookbook steps

### STEP 0 · wire and probe (no TODO)
- Wire SWDIO, SWCLK, GND, 3V3 from the ST-Link to the board. Plug the ST-Link into the PC. Do NOT plug the board's USB.
- **CHECK:** `st-info --probe` prints a chip id and `flash: 32768` for a real C6 (a clone may print a bigger number: the plan still uses 32 KB).

### STEP 1 · TODO M1-03/1 · blink in `main` · [src: M1-03 step 1]
- **WHAT:** Make the LED blink.
- **INGREDIENTS:** `led_init()`, `led_toggle()`, a `volatile` counter, the loop shape from the cheat sheet.
- **HOW:**

```
led_init();
for (;;) {
    led_toggle();
    for (volatile uint32_t i = 0; i < <N>; i++) { }
}
```

| name | value |
|---|---|
| `<N>` | `500000` to start, then tune |

- **WHERE:** `src/main.c`, inside `main`. Replace the stub line `for (;;) { }`. Leave the other TODO comments for later issues.
- **CHECK:** `make firmware` builds with no errors.

### STEP 2 · TODO M1-03/2 · `flash` target · [src: M1-03 step 2; worked example above]

- **WHERE:** `Makefile`, section "firmware", after the `size` target.

- **CHECK:** `make test-active` runs three test files and ends green. (`test_m1_03` turns green only after STEP 4.)

### STEP 4 · TODO M1-03/4 · CI firmware job · [src: M1-03 step 4]
- **WHAT:** Add a second CI job that cross-builds.
- **INGREDIENTS:** the CI job shape from the cheat sheet.
- **HOW:** copy the `host-tests` job and change three things.

| field | host-tests (given) | your `firmware` job |
|---|---|---|
| job name | `host-tests:` | `firmware:` |
| install step | none | `run: sudo apt-get update && sudo apt-get install -y gcc-arm-none-eabi` |
| run step | `make test-active` | `make firmware && make size` |

- **WHERE:** `.github/workflows/ci.yml`, after the `host-tests` job, same indent level. YAML cares about spaces: use spaces, never tabs.
- **CHECK:** `make t T=m1_03` -> `4 Tests 0 Failures`, `OK`.

### STEP 5 · finish (no TODO)
- `git add -A`, `git commit -m "M1-03 done"`, then `git push`. Open the Actions tab on GitHub: both jobs turn green (this is the one step that needs the internet).

## Verify

| Do this | Expect |
|---|---|
| `make t T=m1_03` | `4 Tests 0 Failures 0 Ignored`, `OK` |
| `make flash` | `** Verified OK **` and `** Resetting Target **` |
| Look at the board | the green/blue LED near PC13 blinks about once per second (tune N) |
| GitHub Actions after `git push` | jobs `host-tests` and `firmware` both green |

| If it fails, look here | Likely cause |
|---|---|
| `Error: init mode failed` or no device | the ST-Link wires: SWDIO/SWCLK swapped, or no common GND |
| `UNEXPECTED idcode` | clone chip: add `-c "set CPUTAPID 0x2ba01477"` first |
| `Permission denied` / `LIBUSB_ERROR_ACCESS` | udev rules not applied: log out and in, replug |
| LED never changes but flash says Verified | check `led_init()` is called; the LED is active-low, so toggling is what you want |
| LED blinks too fast to see | raise `<N>` |
| CI firmware job red: `arm-none-eabi-gcc: not found` | the install step is missing in the YAML |
| CI: `mapping values are not allowed here` | YAML indentation is wrong |
