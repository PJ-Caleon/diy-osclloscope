## Learn (about 30 minutes)

**Table-driven settings.** A scope has a few fixed choices: 100 us, 200 us, 500 us, ... per division. Store the choices in an array. The UI only keeps an index. Buttons change the index. Everything else is looked up: `tdiv_us[idx]`. No big `switch`, no magic numbers scattered around.

**Where the sample rate comes from.** The screen shows 8 divisions across 128 pixels, so each division is 16 pixels wide, and each pixel is one sample. If one division lasts `t` microseconds, 16 samples must fit in `t`, so `fs = 16 / t`. In integer maths: `fs = 16 * 1,000,000 / t_us` (card C5).

| time/div | samples per division | sample rate |
|---|---|---|
| 100 us | 16 | 160 kHz |
| 1 ms | 16 | 16 kHz |
| 20 ms | 16 | 800 Hz |

**Why these rates?** All eight divide 72 MHz exactly, so the timer makes them without rounding error (your `sampler_timing` from M2-02 proves that, and the test re-checks it).

**Volts per division.** The plot area has 6 divisions of 8 pixels. At 1 V/div it spans 6 V (you only use 3.3 V of it). At 500 mV/div it spans 3.0 V: a 3.3 V signal clips. At 250 mV/div it spans 1.5 V.

**Stepping safely.** UP and DOWN change the index by +1 or -1. It must stop at the ends: that is `clamp_i`.

**Aliasing warning.** At slow rates (800 Hz) a 1 kHz signal is sampled less than twice per period: the picture and frequency are wrong. Remember this for M6.

## Worked example: a table-driven setting (baud rates)

```c
/* WORKED EXAMPLE (M4-02): a table-driven setting. The index is the setting; the table holds the numbers. */
#include <stdint.h>
#define BAUD_COUNT 4
const uint32_t baud_tab[BAUD_COUNT] = { 9600, 19200, 38400, 115200 };
const char *const baud_label[BAUD_COUNT] = { "9600", "19k2", "38k4", "115k" };

static int clampi(int v, int lo, int hi) { return v < lo ? lo : (v > hi ? hi : v); }

int baud_step(int idx, int delta) { return clampi(idx + delta, 0, BAUD_COUNT - 1); }   /* UP / DOWN button */

uint32_t brr_from_idx(int idx, uint32_t pclk)       /* the table feeds a formula */
{
    return (pclk + baud_tab[idx] / 2u) / baud_tab[idx];
}
```

Your tables are the same idea with different numbers, and your formula is `16 * 1000000 / tdiv_us[idx]` instead of the BRR formula.
